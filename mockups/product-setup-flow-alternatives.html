Five clearer setup flows for feedbacks.dev

Each option distinguishes feedback collection from in-app release announcements and makes code deployment consequences explicit.

Confirmed issue

Most feedback-form appearance and field settings live in snippet attributes. If someone customizes after installing, they usually must replace the snippet. The current flow says “optional after success” without making that redeployment cost obvious. Release announcements already work remotely after the shared embed connects.

Option 1

Install once, manage remotely

The snippet contains only the project key and script URL. The widget fetches its complete configuration from feedbacks.dev. After the first install, placement, labels, fields, colors, captcha, and release announcements update without another code deployment.

Best long-term experience.
Requires extending the bootstrap API and carefully preserving legacy snippet attributes.
